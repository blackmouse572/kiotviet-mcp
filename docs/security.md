# Security model

This worker handles credentials for third-party KiotViet shops. The design follows two non-negotiables (from `plan.md`):

1. **The worker never persists raw credentials at rest.** Bearers are self-contained sealed envelopes; tokens in cache are short-lived and (optionally) AES-wrapped.
2. **No shared in-memory map keyed by `clientId`.** Anyone who learns a `clientId` must not be able to traverse to another shop's session. Every lookup is keyed by a value an attacker can't guess from `clientId` alone.

This doc explains how the implementation honors those, where the trust boundaries are, and what is **out of scope** for v1.

## Trust boundaries

```
   ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
   │   Claude    │     │  Trusted    │     │   KiotViet  │
   │  / BYO MCP  │     │   backend   │     │     IDP     │
   │   client    │     │  (apps/api) │     │  + API      │
   └──────┬──────┘     └──────┬──────┘     └──────▲──────┘
          │  Bearer (sealed)  │ HMAC               │ client_credentials
          │                   │                    │  (from inside bearer)
          ▼                   ▼                    │
        ┌─────────────────────────────────────────┘
        │                  worker (Hono)
        │  - opens envelope in request-scoped memory only
        │  - dispatches via SDK
        │  - caches KiotViet access_token (optionally AES-GCM wrapped)
        └─────────────────────────────────────────────
```

Trust boundaries that matter:

- **Sealed envelope ↔ holder.** Holder (Claude, eccho) cannot read the credentials inside the bearer — only the worker (which has `MCP_BEARER_SK`) can.
- **HMAC ↔ trusted backend.** Anyone with `LINK_HMAC_SECRET` can mint bearers for arbitrary credentials. Treat it like a master key.
- **Worker process memory ↔ everything else.** Credentials live there for the duration of one request, then go out of scope. Nothing on disk, nothing in KV.

## Key material

| Secret | Purpose | Generated by | Compromise impact |
|---|---|---|---|
| `MCP_BEARER_PK` | Public half of the envelope keypair. Used by `seal()` to encrypt bearer payloads. | `generateKeyPairHex()` in `src/auth/envelope.ts` | Low alone — useful only to attackers who already control bearer minting (rare). |
| `MCP_BEARER_SK` | Private half. Used by `open()` to decrypt bearers on `/mcp`. | (same) | **Critical**. Attacker can decrypt every outstanding bearer → recover all linked shops' credentials. Rotate immediately if leaked. |
| `LINK_HMAC_SECRET` | Shared with the trusted backend. Authenticates `/internal/link` + `/tools` calls. | `openssl rand -hex 32` | **Critical**. Attacker can mint bearers for any retailer/clientId/clientSecret they choose — but they need *valid* credentials for KiotViet to accept the validation call. The risk is bypassing your product's link-flow controls. |
| `TOKEN_CACHE_KEY` (optional) | AES-256-GCM wraps cached KiotViet access tokens in KV. | `openssl rand -hex 32` | Medium. Attacker with KV read access *plus* this key can decrypt cached tokens (max ~24h validity). Without the key, KV values are opaque. |

All four live in Workers Secrets in prod (`wrangler secret put`) or `.env` locally (`.env` is gitignored).

## What's stored, and where

### Durable

- **KV namespace `KIOTVIET_TOKENS`** (or in-memory `MemoryStore` in Bun): `sha256(clientId|clientSecret) → {access_token, expires_at}`. TTL = KiotViet's `expires_in` minus a 60-second early-refresh buffer. If `TOKEN_CACHE_KEY` is set, the value is AES-256-GCM encrypted with a per-record random 12-byte IV (`src/store/workers-kv.ts`).
- **Durable Object instance `TokenRefreshAgent`** (Workers only): holds *no* persistent state. It exists purely as a per-key addressable serialization point for single-flight refresh (`src/store/do-lock.ts`).

### Request-scoped only

- Decrypted bearer payload (`{retailer, clientId, clientSecret, iss, exp}`).
- The fresh KiotViet access token (when refresh happens during a request).
- The `KiotVietClient` SDK instance (closed over the credentials).

All three are dropped when the request handler returns.

### Not stored

- **No `clientId`/`clientSecret` ever written to disk, KV, DO storage, or logs.** The token cache is keyed by a SHA-256 hash; the value contains only the access token, never the credentials.
- **No per-bearer state** (no session table, no revocation list, no usage counter) in v1.
- **No PII** beyond the retailer name, which lives inside the sealed bearer.

## Crypto primitives

### Bearer envelope (`src/auth/envelope.ts`)

- **Algorithm**: NaCl `box.seal` equivalent — ephemeral X25519 keypair + XSalsa20-Poly1305, via `tweetnacl`. Each `seal()` call generates a fresh ephemeral keypair; the public half is prepended to the ciphertext.
- **Nonce**: derived deterministically from `(ephemeral_pk || recipient_pk)` via a stable internal hash. Safe because the ephemeral keypair is unique per call, so the nonce is unique even though the derivation is deterministic.
- **Encoding**: base64url.
- **Expiry check**: `open()` rejects on `payload.exp < now` *before* returning the plaintext to the caller.
- **Tamper resistance**: Poly1305 MAC. Any bit-flip → `box.open` returns null → `decrypt failed`.
- **Forward secrecy**: ephemeral X25519 means even if `MCP_BEARER_SK` leaks *after the fact*, past bearers can still be decrypted — there's no PFS for archived bearers. (PFS would require per-session keys, which we don't have because the bearer is the session.)

### HMAC (`src/auth/hmac.ts`)

- **Algorithm**: HMAC-SHA256 via Web Crypto (`crypto.subtle`).
- **Canonical string**: `timestamp + "\n" + METHOD + "\n" + path + "\n" + sha256_hex(body)`. The body hash binds the signature to the exact request body — modifying the body invalidates the signature.
- **Replay protection**: 60-second `nowSec - ts` window. Within that window, replays succeed — if you need stricter, add a nonce-tracking KV entry per signature.
- **Comparison**: `crypto.subtle.verify` is constant-time.

### KV token wrap (`src/store/workers-kv.ts`)

- **Algorithm**: AES-256-GCM with a 12-byte random IV per record, IV prepended to the ciphertext.
- **Key**: `TOKEN_CACHE_KEY` (32-byte hex). Optional — if unset, KV values are stored as plaintext JSON. Recommended in prod.
- **Scope**: protects KV-at-rest. Does **not** protect against an attacker who already has worker-runtime access (they hold `MCP_BEARER_SK` too).

## Threat model

| Attacker capability | Defense | Residual risk |
|---|---|---|
| Steals a bearer in transit | TLS terminates at the worker; bearer is bound to `exp`. | Stolen bearer is fully usable until `exp`. **Mitigation**: short `BEARER_TTL_SECONDS`, key rotation, optional revocation denylist (deferred). |
| Steals KV contents | KV values either opaque (no `TOKEN_CACHE_KEY`) or AES-256-GCM wrapped. | KV holds short-lived access tokens, not credentials. Max impact = use a leaked KiotViet token until its `expires_in` lapses (~24h). |
| Steals `LINK_HMAC_SECRET` | n/a — this is the master key for `/internal/link`. | Attacker can mint bearers for any credentials they have. Defense = treat as a critical secret, rotate on suspicion, narrow the backend's scope of who can read it. |
| Steals `MCP_BEARER_SK` | n/a — this is the master key for opening bearers. | Attacker can decrypt every outstanding bearer → recover all credentials. Defense = rotate immediately; every bearer 401s on next use; all shops re-link. |
| Replays a captured HMAC request | 60-second window. | Within the window, a replay succeeds. **Mitigation**: add per-signature nonce-dedupe KV (deferred). |
| Tampers with bearer | Poly1305 MAC. | `open()` rejects with `decrypt failed` → 401. |
| Tampers with HMAC body | Body hash inside canonical string. | `verify` returns false → 401. |
| DDoS / cost amplification | No rate limit in v1. | Add Cloudflare's edge rate limit rules or a token bucket inside the worker. |
| Cache poisoning via concurrent refresh | Single-flight via Promise map (memory) or DO (Workers). | Concurrent requests for the same `sha256(clientId|clientSecret)` collapse to one upstream call. |
| Traverse from one `clientId` to another shop | Cache is keyed by `sha256(clientId|clientSecret)`, not `clientId`. | Knowing a `clientId` alone yields no lookup. |
| Side-channel on credential validity (timing) | Comparison is via `crypto.subtle.verify`; KiotViet validation is `client_credentials` round-trip. | KiotViet's response time leaks "credential valid vs invalid" — that's true of any IDP. |
| Insider with worker code & secret access | n/a | Treat the worker like any other production service. Audit secret access. |

## Out of scope (v1)

These are deliberate gaps with planned follow-ups in `plan.md`:

- **Per-bearer revocation denylist.** Adds a KV lookup on every `/mcp` request. Deferred until a customer asks. Today's escape hatch is full `MCP_BEARER_SK` rotation.
- **Audit log of `/internal/link` and `/mcp` calls.** Wire your platform's logger; v1 ships none.
- **Rate limiting.** Use Cloudflare's edge rate-limit rules.
- **HMAC nonce-dedupe.** Today's 60-second window allows replays within the window.
- **Forward-secret bearers.** Would require per-session keys; bearers would no longer be self-contained.
- **Encrypted-at-rest credential store in apps/api for silent renewal.** Explicitly traded off — see `docs/auth.md` and the FAQ.

## Operational checklist

Before going to prod:

- [ ] All four secrets set via `wrangler secret put` (none in `wrangler.toml`).
- [ ] `TOKEN_CACHE_KEY` set — opting out only if you accept KV plaintext.
- [ ] `BEARER_TTL_SECONDS` chosen for your revocation tolerance (default 90d).
- [ ] DNS + TLS termination configured (Cloudflare edge or your proxy).
- [ ] `/healthz` is reachable from your monitoring.
- [ ] Trusted backend's `LINK_HMAC_SECRET` matches the worker's (string-equal).
- [ ] Trusted backend stores bearer envelope-encrypted at rest (its existing pattern).
- [ ] Key rotation playbook documented (who does it, who notifies tenants for re-link).
- [ ] Logs do not capture `Authorization` headers or `/internal/link` bodies.
- [ ] Rate limiting wired at the edge.
